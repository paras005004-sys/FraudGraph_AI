# FraudGraph AI — Data Model Specification

> **Status:** FINAL VERIFIED DATA MODEL (Phase 2B Baseline)
> **Authoritative Dataset:** HHGOA_IEEE (`dataset/HHGOA_IEEE/`)
> **Generated Files:** `data/graph_load/vertices/` (7 files) and `data/graph_load/edges/` (9 files)

---

## 1. Source Datasets

1. **`transactions.csv`** (590,742 rows × 397 columns):
   - Core transaction dataset with original Vesta features + added `customer_id`, `ts`, `channel`, `risk_score`.
2. **`identity.csv`** (144,432 rows × 41 columns):
   - Identity, device profile, and network characteristics for online transactions. Joined via `TransactionID`.
3. **`closed_cases_history.csv`** (5,565 rows × 15 columns):
   - Historical bank investigation outcomes (July–Oct 2016): 4,665 confirmed fraud / 900 cleared.
4. **`case_pack.csv`** (20 rows × 8 columns):
   - 20 exam benchmark alerts (`HHG-001` through `HHG-020`) for agent evaluation.

## 4. Empirical Audit Findings

- **OWNS Count (13,933)**: 13,553 cards are derived from `transactions.csv` plus 380 additional card suffixes (`-K2`, `-K3`) present in `closed_cases_history.csv`.
- **ON_CARD Count (5,565)**: Every one of the 5,565 closed historical cases names exactly 1 target card ID (0 missing).
- **CONNECTED_TO Count (92)**: Exactly 4 historical multi-card investigation cases (`CC-2649`, `CC-3102`, `CC-4011`, `CC-4890`) involve shared device/fraud ring networks across 92 secondary cards.
- **NEXT Count (577,189)**: Generated by ordering transactions by timestamp `ts` within each card profile.
